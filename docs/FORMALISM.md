# Mathematical specification

[README](../README.md) · [Design](DESIGN.md) · [Usage](USAGE.md) · [References](REFERENCES.md)

This specification describes the state and transition rules in version 1.1.0.
The equations document the implementation; they have not been machine-checked.
See [Implementation status](IMPLEMENTATION_STATUS.md) for supported features and limits.

## State and notation

| Symbol | Meaning |
| :--- | :--- |
| $a$ | An artifact with a kind, payload, references, author label, and creation time. |
| $D_t=(\mathcal A_t,\mathcal R_t)$ | The persistent artifact graph and its typed references. |
| $\mathcal E_t\subseteq\mathcal A_t$ | Evidence artifacts with a valid kernel authentication tag. |
| $\Phi_t$ | Callable instrument definitions available to research. |
| $G_t$ | A compositional grammar, including learned macros. |
| $\mathcal H_t$ | Decision records and linked realized outcomes. |
| $W_t=(D_t,\Phi_t,G_t,\mathcal H_t)$ | The research world: a logical view over these persistent records. |
| $\Omega_t^m=\Omega(D_t,m)$ | A derived mission view: revision, membership, attention, and restrictions. |
| $\mathcal W_t^m$ | Eligible mission work, including scoped frontier obligations and requests. |
| $\tau_t$ | A selected task, not necessarily generated by the frontier. |
| $C_t$ | The context packet compiled for that task. |
| $j_t,r_t,e_t$ | A declared execution job, its result record, and its signed evidence artifact. |
| $b_t$ | An abstraction proposed for reuse in a subsequent world. |

The components of $W_t$ are not disjoint databases. Instruments, grammar entries, and history are
represented through artifacts and references. Missions, lifecycle records, descriptors and capsule
bundles also live in $D_t$; they do not add coordinates to $W_t$. A mission view is computed, not a
second ledger. Below, $D\subseteq D'$ means componentwise graph inclusion, and $\operatorname{Ids}(C)$
means the IDs represented in a packet; a serialized packet itself is not a set of artifacts.

An artifact's identifier is content-derived:

$$
\mathrm{id}(a)=\mathrm{digest}(\text{kind},\text{data},\text{references},\text{author}).
$$

`core.py` uses a truncated SHA-256 digest for artifact IDs. `BlobStore` uses full SHA-256 digests for retained bytes. Creation time is not part of artifact identity. The ledger's public write operation appends or returns an existing content-identical record.

## Kernel: identity, execution, and authority

### 2.1 The declared job

Conceptually, an execution request is

$$
j=(\text{target},\text{tool},\text{argv},\text{declared inputs},\text{environment},\text{seed},\text{limits}).
$$

`Kernel.use(...)` formats a tool descriptor into such a request. `Kernel.run(...)` executes locally; `WorkerKernel` delegates execution to a worker. The record contains, among other fields,

$$
r=(\text{exit status},\text{stdout},\text{stderr},\text{elapsed time},\text{run metadata}).
$$

The base implementation hashes declared inputs, records runtime settings, and retains bounded stdout/stderr. It does not infer undeclared dependencies.

### 2.2 Authentication, not a theorem

Let $k$ be the kernel's signing key. In schematic form,

$$
\sigma=\mathrm{HMAC}_k(\text{kind},r,\text{references},\text{author}),\qquad
 e=(r,\sigma).
$$

`Kernel.verify(e)` requires a 64-character lowercase hexadecimal tag before comparing HMACs.
Authentication establishes the following distinction:

$$
\mathrm{Verify}_k(e)=\text{true}
\ \not\Rightarrow\
\text{the associated scientific claim is true}.
$$

The tag authenticates a record under a shared secret. Tool semantics, formalization and scientific interpretation require separate validation.

### 2.3 Authority labels

`context.authority(...)` produces:

| Label | Implemented meaning |
| :--- | :--- |
| `proposal_or_state` | A hypothesis, memo, world, or other ordinary record. |
| `retrieved_source` | A source, source text, or retrieval record. |
| `consequence` | An evidence artifact whose kernel tag verifies. |
| `derived_from_consequence` | A supported derived artifact type with reference paths to signed evidence. |
| `untrusted` | An evidence artifact with no valid tag. |

The derivation label describes **provenance linkage** rather than an independent recomputation of the measurement or summary. A proposed claim does not change type because its own payload says `pass`.

### 2.4 Eligibility and promotion

The frontier is a rule-derived set:

$$
\mathcal F(D_t)=\{\tau:\text{a routing obligation is not yet satisfied in }D_t\}.
$$

For a legacy claim, missing signed mathematical execution evidence creates `verify`. An experiment
without evidence in its declared `evidence_lane` (default `empirical`) creates `run`. The rules use
linked records and reported execution verdicts; they are not an exhaustive scientific validity
checker. Explicit-policy claims follow the additional rule below.

`compress(...)` records an invariant from a bridge labeled `agreement`. `promote(...)` accepts an invariant, representation, or mechanism and records a world referencing it:

$$
W_{t+1}=W_t\oplus b_t.
$$

Here $\oplus$ denotes a proposed reusable basis and its lineage. These functions do not themselves rerun validation. Evidence-sensitive acceptance therefore also depends on the calling policy, checker configuration, and deployment boundary.

### 2.5 Explicit checking protocols

For a claim $c$ with `check_policy="explicit"`, let $P(c)$ be experiments whose `checks` reference
contains $c$. Let $E(c)$ be the union of their authenticated `evidence` children on the declared
execution channels. Let $I(c)\subseteq E(c)$ contain those evidence IDs cited by a `resolution`
that targets $c$, has `check_interpretation=1`, and has a nonempty statement. The additional rules are

$$
P(c)=\varnothing\Rightarrow\operatorname{design\_check}(c),\qquad
E(c)\setminus I(c)\ne\varnothing\Rightarrow\operatorname{interpret}(c).
$$

The ordinary experiment rules still schedule `run` when evidence is absent and `repair` when none
of the recorded executions passes. A failed run can therefore require both repair and interpretation.
`protocols.declare_check` records a protocol using a separately registered tool; it installs no code.
`protocols.interpret_checks` verifies evidence authentication and its association with declared checks,
then records a researcher-authored resolution. The frontier recognizes record coverage, not the
correctness of that interpretation. New evidence IDs reopen interpretation; process success does not
establish the checked claim. Claims without the opt-in keep legacy routing. Arbitrary kinds can be
checked through experiments, but this automatic claim-level extension and the legacy study/bridge
rules are not a universal protocol calculus.

## Research, context, and the two streams

### 3.1 Mission-scoped research

The world remains $W_t=(D_t,\Phi_t,G_t,\mathcal H_t)$. A mission conditions attention and delivery,
not scientific authority:

$$
\Omega_t^m=\Omega(D_t,m),\qquad
\mathcal W_t^m=\operatorname{Eligible}_{\Omega_t^m}
\bigl(\Gamma_m(\mathcal F(D_t))\cup Q_t^m\cup O_t^m\bigr).
$$

$Q_t^m$ contains explicit directed, exploratory and challenge requests; $O_t^m$ is the output of
optional opportunity producers. $\Gamma_m$ selects obligations relevant to explicit mission
membership, with a specific provision for stress tasks on shared assumptions. Eligibility checks
access and branch attention; requests additionally check their open state, prerequisites and declared
tool requirements. Execution checks actual tool permissions again. This is not a priority score.
The full-ledger frontier is computed **before** scheduling filters: dormancy defers work rather than
removing the evidence on which obligations are calculated.

The model sees bounded agenda pages, not the whole world:

$$
\tau_t\sim\pi_\theta(\,\cdot\mid\operatorname{Page}(\mathcal W_t^m,\Omega_t^m)\,),\qquad
C_{t,k}=\mathcal C(W_{t,k},\tau_t,\Omega_{t,k}^m;B).
$$

Selection may instead request another page or defer. Origins are displayed and sorted deterministically
for pagination; that ordering is not a scientific utility function and can affect what is seen first.
An empty scoped agenda yields `idle`, not a declaration of scientific completeness. Unscoped callers
retain the legacy frontier selector. No exhaustive exploration or starvation-freedom guarantee is made.

#### Revisions, membership, and causal attention

Missions have a stable root and immutable complete revisions. Both revision and attention updates
name their causal predecessor heads. For records $L_t(x,s)$ concerning subject $x$ in scope $s$, define

$$
\operatorname{Heads}_t(x,s)
=\{\ell\in L_t(x,s):\operatorname{id}(\ell)\notin
             \bigcup_{u\in L_t(x,s)}\operatorname{previous}(u)\}.
$$

No head means the default (`active` for a branch, `open` for a request); one head supplies its state;
multiple heads mean `conflict`, not last-writer-wins. A write must name exactly the observed head set.
Mission revisions use the same head calculation, including their root, and require a unique current
revision for a session. These are serial optimistic checks: they are neither locks nor atomic
compare-and-swap across processes. Existing records remain immutable under the supported API.

Let $S(m)$ contain mission $m$ and its program, if any. Let $B_m(a)$ be the **explicit** owning branches
of an ordinary artifact $a$ in the mission. Then

$$
\operatorname{Active}_m(b)=\bigwedge_{s\in S(m)}
 [\operatorname{state}(b,s)=\text{active}],\qquad
\operatorname{Attend}_m(a)=[B_m(a)=\varnothing]\lor
 \bigvee_{b\in B_m(a)}\operatorname{Active}_m(b).
$$

A branch artifact itself uses $\operatorname{Active}_m$. Branch membership may overlap. Dependency
reachability is not ownership; another active owner can keep shared work eligible. An explicit
program decision can suppress a branch across that program. The access predicate $\chi_m(a)$ is
separate: policies intersect tool allowlists, union denied IDs, and take the earliest declared cutoff.
`reading.available` follows declared dependencies (excluding administrative membership/lineage
roles) and checks source metadata. It does not inspect undeclared inputs or erase model knowledge.
Access, attention and authority are different functions, not statistically independent variables.

A supersession record is a scoped, purpose-qualified preference $(a,b,s,p,r,U)$, with reason $r$ and
support $U$. It is exposed as context; no global order, transitive closure, scientific dominance, or
rewriting of experiments that referenced $a$ is inferred. A challenge is simply a request with the
obstruction, prior attempts and optional methods. Neither operation changes execution authority.

#### Context and exposure

The compiler uses graph locality, ranked lexical retrieval, artifact-kind preferences, descriptor
dependencies and scoped attention. Explicit local search uses permission, not branch activity, as
its filter. Historical evidence may remain contextually relevant when its originating branch is
paused. There is no guarantee that every relevant item fits a finite packet.

Explicit mission requirements and selections demand payloads or caller-selected spans, including
schema-requested dependencies; they cannot be silently reduced to previews. Local task/mission roots
that are not explicitly required may still use marked, recoverable previews. For the complete
model request $U_{t,k}$, containing instructions, context, tools and recent observations, the successful
return condition is

$$
\operatorname{RequiredSatisfied}(R_m,C_{t,k})\ \land\
 \left|\operatorname{Serialize}(U_{t,k})\right|_{\rm chars}\le B.
$$

Unfit required material raises `ContextOverflow`. Optional material can be omitted; oversized results
can be retained behind readable handles. This is a deterministic packing policy, not optimal
information selection. Character bounds are exact for the produced serialization; token bounds are
estimates. The initial packet is not an access boundary: subsequent actions can inspect, search,
read passages and use permitted instruments. Search still uses the existing provider set and lexical
local backend; neither generalized search nor schema evolution is added by this formalization.

Let $X_{t,k}$ be the union of spans actually delivered up to turn $k$, keyed by artifact ID and original
field. A candidate citation must lie inside a covered interval for that same key. Only server-generated
views contribute exposure; an ID mentioned inside source text is not exposure. Membership of $X$ proves
neither comprehension nor entailment, and exposure tracking restarts for a new session.

#### Descriptors are contracts, not authority

An optional descriptor $s$ defines $\operatorname{Conform}_s(a)$ as the conjunction of its field
requirements and reference-count/kind requirements. Its context dependencies are the referenced
IDs marked `context=true`, plus the descriptor ID. The compiler still enforces permissions and
budget. A tool can require conformance of its input values before execution. Unknown descriptors
fall back to inspection with a diagnostic; neither conformance nor a richer display authenticates
an observation or establishes scientific correctness. Version references are exact; no automatic
schema evolution, migration or adoption policy is implied.

#### One action lifecycle

An entry in `actions.py` binds a prompt argument description to a handler, availability conditions,
a membership policy and, optionally, read-only attempt preparation. Descriptions are not a general
validation language; handlers and underlying APIs enforce their own inputs. A researcher cannot
install handlers by writing artifacts. The same registry advertises and dispatches available actions.
For an advertised action $u_{t,k}$:

$$
u_{t,k}\sim\pi_\theta(\cdot\mid U_{t,k}),\quad
 d_{t,k}=\operatorname{Commit}(U_{t,k},u_{t,k}),\quad
 z_{t,k}=\operatorname{Handle}(u_{t,k}),\quad
 o_{t,k}=\operatorname{RecordOutcome}(d_{t,k},z_{t,k}).
$$

The session rechecks the mission revision and current branch after the model call. A changed scope or an unadvertised action prevents handler invocation. Input validation occurs
inside handlers and called APIs; a rejected input may follow partial writes (for example stored
candidates before invalid activation indices). Handlers return a common result: observation,
produced/observed references, summary and an optional terminal return. Only the loop attaches automatic
membership and appends the outcome. New investigations keep their explicitly chosen ownership instead
of inheriting the caller's branch. Candidate validation lives beside activation in `propose.py`;
explicit `activate=[]` does not activate anything.

There is one outcome-recording path for normally completed and recoverable-error turns. A crash,
unexpected programming error or failed ledger write can leave an unmatched decision or partial writes;
this is not a durable exactly-once protocol. Preparation is read-only; some handlers write several
artifacts and are not transactional. The state digest records the fitted prompt, not an unbounded
world snapshot. When a handler invokes an execution, that job alone crosses the unchanged kernel
boundary. Otherwise it produces ordinary research/control records. With the append-only API and
unmodified stored payloads, each completed update is $D'=D\cup\Delta D$; new worlds and instruments
retain their existing reuse semantics.

### 3.2 Mathematical execution

A formalization $\tilde p$ is submitted to a chosen checker:

$$
r^M=\mathrm{Exec}_M(\tilde p),\qquad e^M=K(j^M,r^M).
$$

Installed backends may include Lean, SMT solvers, symbolic checks, and executable Python checks. These have different semantics. A returned result must be interpreted in its formalism and under its assumptions; a failed process is not automatically a counterexample.

### 3.3 Empirical execution

An experimental protocol $\mathcal P$ maps data, initialization, hyperparameters, and environment to measured output:

$$
Y=\mathcal P(D,S,\Lambda,E).
$$

Repeated runs yield $Y_1,\ldots,Y_n$ and a derived summary $\mathcal S(Y_1,\ldots,Y_n)$. Source preservation and signed execution are distinct from analysis:

$$
\text{execution record}\ne\text{reported measurement}\ne\text{scientific conclusion}.
$$

Summary functions provide estimates, dispersion, intervals, quantiles, and contrasts. Their statistical interpretation depends on sampling, dependence, and stopping assumptions. Formal and empirical evidence are never combined into a single confidence scalar.

## Scientific transformations

These operators primarily live in [`ops.py`](../src/recursive_discovery/ops.py). They are replaceable scientific policies, not additional powers of the signing kernel.

### 4.1 Assumption → intervention

For a scalar predicate $x\mathbin{\triangleleft}c$, `stress(...)` proposes a small boundary-crossing set, schematically

$$
\mathcal I(A)=\{c-\epsilon,c,c+\epsilon\}.
$$

The ordering depends on the comparison operator. This is a finite intervention proposal for one scalar predicate, not a general method for testing arbitrary mathematical assumptions.

### 4.2 Discrepancy → localized question

For prediction $\hat y_i$, observation $y_i$, and supplied assumption flags $A_{ij}$,

$$
\delta_i=\mathbf 1[d(\hat y_i,y_i)>\text{tolerance}],\qquad
s_i=\bigwedge_j A_{ij}.
$$

The diagnosis distinguishes mismatch inside and outside declared scope:

$$
\delta_i=1,\ s_i=0\Rightarrow\text{investigate scope},\qquad
\delta_i=1,\ s_i=1\Rightarrow\text{investigate an in-scope discrepancy}.
$$

It may summarize the observed association of an assumption with mismatch:

$$
L(A)=\widehat P(\delta=1\mid\neg A)-\widehat P(\delta=1\mid A).
$$

This is descriptive, not causal. `diagnose(...)` uses caller-supplied flags; it does not independently verify the assumptions. In-scope disagreement can also arise from a bad formalization, implementation defect, numerical error, or measurement error—not only from a missing theory. Missing assumption flags require care: the current operator treats absent flags as false.

### 4.3 Observations → competing conjectures

The initial conjecture operator searches simple one-feature rules. For a rule $h$,

$$
\widehat{\mathrm{accuracy}}(h)=\frac1n\sum_i\mathbf1[h(x_i)=y_i].
$$

The best rule per feature can remain available for discrimination. Agreement on observed cases is not proof or evidence of a causal mechanism.

### 4.4 Competing explanations → discriminating experiment

Let $H$ be a random variable over live deterministic hypotheses with supplied weights. Under a fixed candidate intervention $u$, each hypothesis predicts $Y_u=f(H,u)$. Then

$$
\mathrm{IG}(u)=\mathrm I(H;Y_u)=\mathsf H(Y_u),
$$

because $\mathsf H(Y_u\mid H)=0$. The supplied heuristic selects

$$
u^*\in\arg\max_u\frac{\mathrm{IG}(u)}{c(u)}.
$$

Here $c(u)$ is a declared experimental burden. This local heuristic is separate from model-owned task selection. It assumes deterministic predictions and a fixed candidate set; noisy likelihoods require a different policy.

After observation $y$, resolution retains

$$
\mathcal V' = \{h\in\mathcal V:d(f(h,u),y)\leq\epsilon\}.
$$

An empty survivor set is recorded as surprise. It means the supplied hypotheses did not predict this observation within tolerance, not that every possible explanation has been falsified.

### 4.5 Surprise → representation or mechanism proposal

On a finite case set $S$, the current diagnostic computes empirical conditional entropy using exact coordinate matches:

$$
\widehat U_S(C)=\widehat{\mathsf H}_S(Y\mid C),\qquad
\widehat{\Delta U}_S(z)=\widehat U_S(C)-\widehat U_S(C,z).
$$

Positive empirical entropy detects outcome variation within represented states. An observable that reduces it is a candidate refinement. Zero entropy merely means the supplied cases show no such collisions; with unique continuous coordinates it can occur trivially. Neither outcome proves representation sufficiency or establishes a missing causal variable. Noise can also produce conditional variation.

`expand_representation(...)` uses this limited diagnostic to return `expanded`, `blind`, or `mechanism`. These are routing suggestions on the supplied data.

### 4.6 Instrument and mechanism synthesis

An instrument is a transformation $\phi:X\to Z$. The search policy can rank a candidate by empirical ambiguity reduction relative to measurement and description cost:

$$
q(\phi)=\frac{\widehat U_S(C)-\widehat U_S(C,\phi(X))}
 {c_{\mathrm{measure}}(\phi)+c_{\mathrm{description}}(\phi)}.
$$

Mechanism search uses a small expression grammar and an affine readout:

$$
\hat Y=a\,\phi(C)+b.
$$

Candidates are fitted and ranked by error and a simplicity tie-break. This is a bounded synthesis policy, not a universal scientific learner. Prospective checker results and supplied data determine what the surrounding policy accepts.

### 4.7 Persistent workbench instruments

The interactive workbench has a separate lightweight definition path. A model declares inputs, an expression, and interface cases. After those cases pass, the definition is available to future workbench instances:

$$
\Phi_{t+1}=\Phi_t\cup\{\phi\}.
$$

A callable definition has passed only the supplied interface cases. It has not been proved correct over its entire domain or shown scientifically useful. The expression interpreter has a fixed function vocabulary; this path is not an unrestricted language-extension or arbitrary-code facility.

### 4.8 Grammar recursion

The synthesis grammar can name a useful composite $m_n$:

$$
G_{n+1}=G_n\cup\{m_n\}.
$$

This turns a deeper expression into a shallow symbol for later search. Search can retain only one representative of a task-local behavior signature:

$$
p\sim_S q\iff p(x_i)=q(x_i)\quad\text{for all }x_i\in S.
$$

Finite-sample equivalence is not mathematical equivalence. A future case can distinguish two programs that were indistinguishable on $S$. The grammar helpers and the interactive expression workbench are related mechanisms, not one automatically unified registry.

## History and prospective evaluation

### 5.1 Decision records

Before an action is executed, record

$$
d_j=(h_j,a_j,p_j,v_j,\pi_j,\mathrm{parent}_j),\qquad
h_j=\mathrm{hash}(s_j).
$$

$p_j$ summarizes the action payload; $v_j$ identifies visible artifacts and action/tool choices. A later `decision_outcome` references $d_j$ and its observed or produced artifacts.

$$
\mathcal H_t=\{(d_j,o_j)\}_{j\leq t}.
$$

The current lookup is an index:

$$
\mathrm{Lookup}(\mathcal H,h,a)
 =\{o_j:h_j=h\ \land\ \mathrm{name}(a_j)=a\}.
$$

Lookup may return several outcomes for a state digest and action name. Callers must inspect their payloads and provenance. Stored digests and selected references do not reconstruct the full context or unvisited branches.

### 5.2 Prospective commitments

A commitment links a proposal and test handle with predictions, a metric, and a decision rule:

$$
\kappa=\mathrm{id}(p,\text{test handle},\hat Y,\mu,\rho).
$$

The intended ordering is

$$
t_{\mathrm{commit}}<t_{\mathrm{observe}}.
$$

The local vault and the evaluator-service adapter support one-use tests and retained evaluation records. Their security depends on actual separation of files, processes, keys, and credentials. Recording a commitment does not prevent leakage through another access path, and a publication-date filter does not remove knowledge already in a model.

### 5.3 Attempt history

`replay.execution_attempt` hashes a declared procedure: targets, artifact inputs, tool, values,
formatted command, current file digests or input errors, seeds, protocol and working directory.
Session instrument attempts instead identify target/tool/spec. Histories join decisions, outcomes
and authenticated records. Equality of signatures means equality of the serialized description,
not scientific redundancy; replication remains allowed. Pre-execution file hashes are not atomic
input snapshots, and direct low-level kernel calls need not have session/runtime decisions.

### 5.4 Immutable capsules and reviewed return

Use $\beta$ for a capsule, reserving $\kappa$ above for a prospective commitment. Let
$S_t=\{\operatorname{id}(a):a\in\mathcal A_t,\ a\text{ is not a capsule-format bundle}\}$.
Compilation freezes a manifest $M_\beta$: mission and revision, compiler fingerprint, snapshot address
and digest, policy, complete selected payloads or exact spans, handles and budget. Then

$$
 h_\beta=H(\operatorname{Canonical}(M_\beta)).
$$

This **delivery ID** is distinct from the ledger's bundle artifact ID. The manifest and rendered body
are stored separately by content digest. Cache identity includes compilation inputs and current
evidence verification results. The compiler checks that $S_t$ has not changed while constructing the
delivery; this detects mixed reads in ordinary serial use but is not snapshot isolation against all
concurrent mutations. Old capsule bytes remain valid historical deliveries after new information.

For a later snapshot $S_u$, let $T_{\beta,u}$ be newly added artifacts with references into delivered
items or the mission root. The actual change report is

$$
 \Delta_{\beta,u}=(S_u\setminus S_t,\ S_t\setminus S_u,\ T_{\beta,u},\
                  [S_u\ne S_t],\ \rho_u(m)).
$$

Its review digest hashes **the entire report**, including current revision and changed flag. Thus new
inbound evidence is noticed even when the target is immutable; unrelated additions also force review.
A return stores raw bytes first, normalizes structured contributions as candidates, and validates
handles and cited spans against the frozen delivery. Freeform prose is retained, not automatically
semantically normalized. Admission requires matching reviewed revision and report digest, valid
unactivated selections, an active destination branch when supplied, current dependency permissions,
and a nonempty review reason. It records admission before ordinary activation. That review is not a
proof of the returned statements, and these sequential checks do not make the multi-write operation
atomic. Hash equality assumes intact bytes and collision resistance, not correctness of the research.

## Operational invariants

The following properties assume serial operations, a fixed signing key, intact stored payloads
and fresh IDs. Direct modification of files or ledger records falls outside these assumptions.

1. **Attention does not adjudicate.** Adding only attention, membership or supersession records leaves
   the raw frontier unchanged: $\mathcal F(D\cup\Lambda)=\mathcal F(D)$. The frontier rules do not match
   those management kinds. The scoped agenda may nevertheless change. Deferred work is not discharged.
2. **Management does not authenticate.** For an existing record $e$, management-only additions leave
   $\operatorname{Verify}_k(e)$ unchanged because its authenticated fields and $k$ are unchanged.
   Normalized responses cannot create evidence/control kinds. Instrument handlers can invoke the kernel.
3. **Successful delivery is bounded, not complete.** `fit_request` returns only when the complete JSON
   fits $B$, or raises when mandatory content cannot fit. This bounds delivery size; access checks still depend on declared
   metadata, and execution requires worker isolation.

Regression tests exercise these properties. See [Session implementation](REFACTOR.md) for the
module and test mapping.

## Observability is an external projection

The world remains $W_t=(D_t,\Phi_t,G_t,\mathcal H_t)$. Reserve $\mathcal E_t$ for authenticated
scientific records and use $\mathcal T_n$ for the separate telemetry sequence. An instrumented
operation produces both its ordinary research result and, when enabled, a best-effort observation:

$$
(D_t,u_t)\longmapsto(D_{t+1},o_t),\qquad
\mathcal T_{n+1}=\mathcal T_n\mathbin{\|}\operatorname{Capture}_c(q_n).
$$

Here $q_n$ is curated operation metadata and optionally content, $c$ is the operator-selected capture
mode, and $\|$ appends only successfully recorded events. Disabled, failed or over-budget capture
may append nothing. Telemetry does not become an artifact in $D$. Captured IDs and references are
observations, not new scientific evidence or unrestricted live reads of the scientific database.
An explicit future import of telemetry into research would require a separate provenance operation;
none is implemented. The recorder does not load a signing key or independently verify evidence.

Each span has an external trace ID, span ID and optional parent ID. Mission, session, task target,
turn, decision and artifact identifiers associate observations with existing records. These external
IDs do not enter prompts, scientific identity inputs or signed payloads. For a fixed already-prepared
request $U$, the model-call wrapper passes $U$ unchanged; it may separately record its character length
and a redacted copy. Compiler candidates and actual delivered exposure are separate events. Neither
an omitted candidate nor a recorded exposed span establishes what the model would have reasoned.

An initial inventory is observed at capture time, not at the artifacts' historical creation times.
Missing events, bounded audits and uninstrumented writes limit the captured history. Wall-clock
timestamps, observation sequence and causal lifecycle predecessor heads are different orderings.
Incomplete spans retain missing end events.

Content capture is off by default and uses best-effort redaction. Event limits and sink failures
appear in recorder health when the store is writable. Synchronous writes affect elapsed time.
Keep telemetry outside worker-accessible directories. See [Telemetry](OBSERVABILITY.md).
